# HW3. Как запустить семантический анализатор Funny

Решение [задания HW3](HW03_types.md): проверки имён и типов поверх AST из HW2.
На вход подаётся программа на Funny. На выходе — JSON с аннотированным AST,
таблицей символов и списком ошибок. Программа не исполняется.

## 1. Подготовка и первый запуск

Нужен **Python 3.10 или новее**. Дополнительные пакеты и сборка не требуются.
Откройте терминал в корне репозитория `TVDSL`:

```bash
cd homeworks/hw3
python3 --version
python3 -B checker.py --text 'function f(x:int) returns r:int {r=x+1;}'
```

Дальнейшие команды выполняются из `homeworks/hw3`. На Windows вместо `python3`
можно использовать `python`, если так запускается установленный интерпретатор.
Ключ `-B` запрещает создание `__pycache__`.

В результате должны быть:

- `ast` — дерево программы; у выражений добавлено поле `inferred_type`;
- `symbols` — таблица функций, параметров, возвратов, локальных переменных
  и переменных кванторов;
- `diagnostics: []` — ошибок нет.

Например, узел сложения будет содержать `"type": "Binary"`, `"operator": "+"`
и `"inferred_type": "int"`. Типы также записываются у его операндов.

## 2. Запуск из файла

Готовый пример с массивами, контрактами, циклом и условием:

```bash
python3 -B checker.py --file examples/good_types.funny
```

Также можно передать путь к своему файлу в UTF-8 через `--file`.
Нужно выбрать ровно один способ ввода: `--text` или `--file`.
Результат выводится в терминал; чтобы сохранить его:

```bash
python3 -B checker.py --file examples/good_types.funny > result.json
```

## 3. Как проверить пункты задания

### Пункт 1. Таблицы символов и проверки имён

```bash
python3 -B checker.py --file examples/bad_names.funny
```

Ожидаются две ошибки: повторное объявление параметра `x` и неизвестная
переменная `missing`. У ошибок есть строка, столбец и смещение.

Проверяются уникальность имён, поиск в текущей и внешних областях,
видимость параметров, возвратов и локальных, области переменных кванторов.
Обычные локальные объявляются в `uses` перед телом функции:

```text
f() returns r:int uses tmp:int {tmp=1;r=tmp;}
```

Присваивание `tmp=1` само по себе не объявляет новую переменную.

### Пункты 2–3. Типы, сигнатуры и унификация

Положительный пример с рекурсивным вызовом:

```bash
python3 -B checker.py --file examples/good_recursion.funny
```

Ожидается `diagnostics: []`. Сигнатуры регистрируются до разбора тел, поэтому
можно вызывать функции, определённые ниже, и использовать взаимную рекурсию.

Отрицательные примеры:

```bash
python3 -B checker.py --file examples/bad_types.funny
python3 -B checker.py --file examples/bad_calls.funny
python3 -B checker.py --file examples/bad_tuple.funny
```

Ожидаемые ошибки:

| Файл | Что обнаруживается |
| --- | --- |
| `bad_types.funny` | Массив в арифметике, целое условие `if`, логический индекс массива |
| `bad_calls.funny` | Неверный тип аргумента, неверное количество аргументов, неизвестная функция |
| `bad_tuple.funny` | Несовпадение количества переменных и результатов, многозначный вызов внутри выражения |

Унификация в выбранном подмножестве — точное совпадение простых типов
без неявных преобразований. Например, `int` совместим с `int`, но не с `int[]`
или `bool`. При выводе типа локальная переменная связывается с типом правой
части первого корректного присваивания.

### Пункт 4. Несколько ошибок с позициями

```bash
python3 -B checker.py --text 'f() returns r:int {r=missing; assert 1;}'
```

Ожидаются две независимые ошибки: неизвестное имя `missing` (строка 1,
столбец 22) и тип `int` вместо `bool` в `assert` (столбец 38).
Одна ошибка внутри выражения не порождает повторные сообщения о типах
во всех его родительских узлах.

У семантической диагностики есть поля:

```json
{
  "phase": "semantic",
  "code": "unknown_name",
  "message": "Переменная 'missing' не объявлена в этой области",
  "node_type": "Name",
  "offset": 21,
  "line": 1,
  "column": 22
}
```

При несовпадении типов дополнительно выводятся `expected` и `actual`.

### Пункт 5. Аннотированный AST

```bash
python3 -B checker.py --file examples/good_formulas.funny
```

Ожидается `diagnostics: []`. У чисел, имён, вызовов, операций, индексации
и кванторов записан `inferred_type`. Предикаты и кванторы имеют тип `bool`.
У объявлений и ссылок на имена есть `symbol_id` — связь с `id` в `symbols`.

### Бонус. Вывод типов локальных переменных

```bash
python3 -B checker.py --file examples/good_inference.funny
python3 -B checker.py --file examples/bad_inference.funny
```

В первом примере локальные `head`, `copy`, `n` объявлены без типов в `uses`.
Выводятся соответственно `int`, `int[]`, `int`; `annotation` остаётся `null`,
а выведенный тип появляется в `inferred_type` и таблице символов.

Во втором примере `tmp` сначала получает тип `int`, затем ему присваивается
массив — это конфликт. Для `unused` нет присваивания — вывести тип невозможно.
Чтение локальной без типа до первого корректного присваивания тоже ошибка.
Корректное обновление `a[i]=42` также задаёт тип локальной `a` как `int[]`.
Это вывод типа, а не проверка инициализации массива для исполнения.

### Дополнительно. Параметры и области контрактов

```bash
python3 -B checker.py --file examples/bad_parameters.funny
python3 -B checker.py --file examples/bad_contract_scope.funny
```

В первом примере запрещается запись в параметр и элемент параметра-массива.
Во втором `requires` ошибочно использует возвращаемое значение, а `ensures` —
локальную переменную. Доступные имена зависят от места:

- `requires` — только параметры;
- `ensures` — параметры и возвращаемые значения;
- тело, `invariant`, `assert`, `assume` — параметры, возвраты и локальные;
- переменная квантора — только внутри его предиката, без перекрытия
  уже видимых переменных. В отдельных кванторах имя можно использовать повторно.

## 4. Запуск тестов

```bash
python3 -B -m unittest -v test_checker.py test_parser.py
```

Запускаются проверки HW3 и сохранённые тесты парсера HW2.
Ожидаемый итог — **77 тестов** (51 для HW3 и 26 для HW2), затем `OK`.

В [test_checker.py](test_checker.py) явно заданы ожидаемые типы и коды ошибок.
Покрыты все примеры из `examples`, вывод типов, области видимости, рекурсия,
массивы, кортежи, позиции, отсутствие каскадных сообщений, CLI и повреждённые
входы. [test_parser.py](test_parser.py) проверяет лексер, грамматику и AST из HW2.

Коды завершения CLI: `0` — проверка без ошибок, `1` — ошибки программы
или чтения файла, `2` — неверные аргументы. Для отрицательных примеров код `1`
ожидаем. После лексических или синтаксических ошибок семантический проход
не запускается: возвращается результат парсера и пустой `symbols`.

## Поддерживаемые типы и ограничения

| Тип | Где используется |
| --- | --- |
| `int` | Параметры, возвраты, локальные, арифметика, индексы |
| `int[]` | Одномерные массивы, копирование, индексация, функциональное обновление |
| `bool` | Внутренний тип условий, предикатов, логических операций и формул |
| `tuple[int, int[]]` и подобные | Результат многозначного вызова в присваивании кортежа |
| Сигнатура функции/формулы | Тип определения в AST, параметры и результаты в таблице символов |

Поддерживаются все узлы парсера HW2: функции, формулы, блоки, присваивания,
`if`/`while`, `assert`/`assume`, контракты, кванторы, вызовы и массивы.
Арифметика и сравнения требуют `int`, логические операции — `bool`.
`length(int[])` возвращает `int`; `a[i]` требует массив и целый индекс.
`ArraySet` сохраняет тип `int[]`, индекс и новое значение должны быть `int`.

Ограничения выбранного подмножества и краткий отчёт:

- Синтаксис и позиции берутся из HW2. Алфавит ASCII, в том числе комментарии;
  нужна стрелка `->`, а не `→`. Сохраняются приоритеты и правила грамматики
  [grammar.ebnf](grammar.ebnf). `else` относится к ближайшему `if`.
- Строки, перегрузки, приведения и переменные типа `bool` не поддерживаются:
  в Funny объявления имеют тип `int` или `int[]`. Нельзя вывести `bool` локальной.
- Массивы одномерные. Повторную индексацию, которую допускает парсер HW2,
  семантический анализ отклоняет. Сравнения массивов и логических значений
  через `==` также не входят в выбранную грамматику сравнений целых.
- Формулы и кванторы разрешены только в предикатах: контрактах,
  `assert`/`assume`, инвариантах и телах формул. В обычном условии `if`/`while`
  они не разрешены. Аргументы вызовов — обычные выражения.
- Локальные объявляются в `uses`; объявлений `var` внутри блоков в грамматике
  HW2 нет. Блоки создают вложенную область поиска, но новых переменных не вводят.
  Локальная может перекрыть имя глобальной функции, однако вызвать её тогда нельзя.
- Тип выводится при обходе присваиваний в порядке исходного текста, в том числе
  внутри ветвей и циклов. Это не анализ гарантированной инициализации по путям.
  Чтение объявленной переменной с известным типом до записи не проверяется;
  по спецификации такое чтение неопределено при исполнении.
- Не выполняются доказательство контрактов, проверка границ массивов,
  деления на ноль, исполнение или генерация кода. Проверяются имена и типы.
- Примеры курса не всегда согласованы с этими правилами: некоторые содержат
  не-ASCII комментарии, локальные без `uses` или запись в параметр даже в `good_*`.
  Исходные файлы не изменяются; для показа HW3 используйте папку `examples`.

Файлы парсера, лексера, автоматов, грамматики и тестов HW2 скопированы без
изменений из ветки `hw2`, коммит `a771e3e426f67db7abcb494d571833537aefed00`.
Поэтому HW3 запускается самостоятельно: переключать ветку или запускать HW2
перед ней не требуется. Спецификация Funny — [funny.ru.md](../../funny.ru.md).

Из папки `homeworks/hw3`:

```python
from checker import check

result = check("f() returns r:int uses x {x=1;r=x;}")
if result["diagnostics"]:
    print(result["diagnostics"])
else:
    typed_ast = result["ast"]
    symbols = result["symbols"]
```

Структура узлов HW2 сохранена. Добавлены `inferred_type` и, для связанных
с именем узлов, `symbol_id`. Таблица `symbols` содержит `id`, `name`, `kind`,
`scope`, `pos`, `inferred_type`, `mutable`; у вызываемых определений также
`parameters` и `returns`. Значения целочисленных литералов остаются строками
цифр, как в HW2. При ошибке типа используется `<error>`, при невыведенном типе
объявления — `<unknown>`. Для следующего этапа используйте результат только
при пустом `diagnostics`.
