# HW1: лексер языка Funny

Лексер строит НКА по алгоритму Томпсона, преобразует его в ДКА и минимизирует
алгоритмом Хопкрофта. Затем автомат можно использовать для разбора текста
или экспортировать в JSON.

## Требования и запуск

Нужен Python 3.10 или новее. Внешние зависимости не требуются.
Все команды ниже выполняются из корня репозитория.

Построить автомат и вывести число состояний:

```sh
python3 -B homeworks/hw1/lexer.py
```

С текущей спецификацией результат: НКА — 295 состояний, ДКА — 125,
минимальный ДКА — 122; стартовое состояние — 0, ловушка — 1.

Разобрать строку:

```sh
python3 -B homeworks/hw1/lexer.py --text 'function f(x:int) returns r:int {r=x+1;}'
```

Результат — JSON-массив пар `[тип токена, текст]`. Пробелы и комментарии
пропускаются. При лексической ошибке выводится сообщение с позицией
(смещение от нуля), код завершения — 1.

Разобрать исходный файл в UTF-8:

```sh
python3 -B homeworks/hw1/lexer.py --file program.funny
```

Готовый пример — [example.funny](example.funny): функция `sum_to(n)` вычисляет
сумму чисел от 1 до `n` (например, `sum_to(5)` даёт 15). В примере есть
предусловие, постусловие и цикл с инвариантом.

```sh
python3 -B homeworks/hw1/lexer.py --file homeworks/hw1/example.funny
```

HW1 выполняет лексический разбор и выводит токены; для вычисления результата
программы понадобится интерпретатор или компилятор Funny.

Экспортировать минимизированный автомат:

```sh
python3 -B homeworks/hw1/lexer.py --export /tmp/hw1-dfa.json
```

`--export` без пути выводит JSON в стандартный вывод. Для одновременного
разбора и экспорта укажите путь: `--text 'x=42;' --export /tmp/hw1-dfa.json`.
`--text` и `--file` взаимоисключающие.

## Спецификация языка

Лексическая спецификация хранится в [language_spec.json](language_spec.json).
`lexer.py` загружает её при импорте, находя файл рядом с собой, поэтому запуск
не зависит от текущей папки. После изменения спецификации запустите программу заново.

- `keywords` — ключевые слова; имя токена получается переводом в верхний
  регистр, кроме `int`, для которого используется `TYPE_INT`.
- `symbols` — соответствие литералов операторов и разделителей именам токенов.
  Литералы автоматически экранируются для построителя регулярных выражений.
- `tokens` — упорядоченный список правил с полями `kind` (имя), `pattern`
  (регулярное выражение), `skip` (пропускать ли токен).

Поддерживаются конкатенация, `|`, группы `()`, повторения `*`, `+`, `?`,
классы символов и диапазоны `[]`, отрицательные классы `[^...]`,
экранирование символов и последовательности `\t`, `\r`, `\n`.
В JSON обратную косую черту нужно удваивать: `"\\t"`.

Приоритет правил: ключевые слова, затем `tokens`, затем `symbols`.
Выбирается самое длинное совпадение; при равной длине — первое правило.
Алфавит — ASCII (коды 0–127), регистр значим. Идентификаторы:
`[A-Za-z_][A-Za-z0-9_]*`, целые числа: `0|[1-9][0-9]*`.
Сканер дополнительно запрещает ведущие нули (`00`, `01`). Знак минус — отдельный
токен. Комментарии начинаются с `//` и заканчиваются перед CR/LF либо в конце
входа. Non-ASCII запрещён в том числе внутри комментариев; непокрытые символы
попадают в ловушку и вызывают ошибку.

Экспорт содержит правила, таблицу переходов для всех 128 кодов ASCII,
принимающие состояния (индексы правил), старт, ловушку и политику сканирования.

## Проверка

```sh
python3 -B -m unittest discover -s homeworks/hw1 -p 'test_lexer.py' -v
```

Тесты проверяют токены и ошибки, весь ASCII, приоритеты, эквивалентность
и минимальность автоматов, сериализацию и интерфейс командной строки.
Условие задания находится в [hw1.md](hw1.md).
