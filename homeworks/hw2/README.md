# HW2. Как запустить парсер Funny

Программа принимает текст на Funny и выводит AST (дерево программы) и список
ошибок в JSON. Это синтаксический анализатор: он не исполняет программу
и не проверяет типы или объявления переменных — это следующие этапы.

Условие: [HW02_parsing.md](../HW02_parsing.md).

## 1. Подготовка и первый запуск

Нужен **Python 3.10 или новее**. Дополнительные библиотеки, сборка, Flex
и Bison для этого решения не требуются.

Откройте терминал в корне репозитория `TVDSL` и выполните:

```bash
cd homeworks/hw2
python3 --version
python3 -B parser.py --text 'function f(x:int) returns r:int {r=x+1;}'
```

Все дальнейшие команды выполняются из папки `homeworks/hw2`.
На Windows, если Python запускается командой `python`, замените `python3`
на `python`. Ключ `-B` запрещает создание файлов `__pycache__`.

В терминале появится JSON с двумя полями:

- `ast` — дерево с узлами `Module`, `Function`, `Block`, `Assign` и выражениями;
- `diagnostics` — список ошибок. Для этого примера он должен быть пустым: `[]`.

У каждого узла дерева есть `type`, `pos` и поля соответствующей конструкции.
В `pos` записаны `offset` (смещение от 0), `line` и `column` (строка и столбец от 1).

## 2. Запуск программы из файла

Разберите готовый пример из репозитория:

```bash
python3 -B parser.py --file ../../project/examples/step01/good_basic.funny
```

Для своего примера сохраните текст на Funny в UTF-8, например в `example.funny`
в текущей папке, и выполните:

```bash
python3 -B parser.py --file example.funny
```

Минимальное содержимое такого файла:

```text
function f(x:int) returns r:int {
    r = x + 1;
}
```

Нужно передавать ровно один аргумент: `--text` или `--file`.
Результат выводится в терминал. При необходимости сохраните его в файл:

```bash
python3 -B parser.py --file example.funny > result.json
```

## 3. Проверка конструкций по заданию HW2

Каждую команду можно запускать отдельно. В правильных примерах ожидается
`diagnostics: []`.

### Приоритеты и ассоциативность

```bash
python3 -B parser.py --text 'f() returns r:int {r=1+2*3;}'
python3 -B parser.py --text 'f() returns r:int {r=8-3-1;}'
```

В первом дереве внутри `Binary` с оператором `+` справа должен находиться
`Binary` с оператором `*`: `1+(2*3)`.
Во втором слева у последнего вычитания будет ещё одно вычитание: `(8-3)-1`.

### Контракты, if, while, блоки, assert и assume

```bash
python3 -B parser.py --text 'f(x:int) requires x>=0 returns r:int ensures r>=0 {assume x>=0; r=x; if(r>0) {r=r-1;} else {r=0;} while(r>0) invariant r>=0 {r=r-1;} assert r==0;}'
```

В AST должны появиться поля `requires`, `ensures`, узлы `If`, `While`,
`Block`, `Assert` и `Assume`. Это проверка разбора, а не доказательство контрактов.

Пустые контракты тоже принимаются; тело удобно записывать в фигурных скобках:

```bash
python3 -B parser.py --text 'f() requires returns r:int ensures {r=1;}'
```

### Чтение и обновление массива

```bash
python3 -B parser.py --text 'f(a:int[]) returns b:int[] {b=a; b[0]=a[1]+1;}'
```

Чтение `a[1]` представлено узлом `Index`. Обновление `b[0]=...` превращается
в `Assign`, у которого значение — узел `ArraySet`. Этот узел обозначает
функциональное обновление: создание копии массива с изменённым элементом.
В HW2 строится только дерево; само копирование здесь не выполняется.

## 4. Ошибки и продолжение разбора

### Пропущено выражение

```bash
python3 -B parser.py --text 'f() returns r:int {r=; x=2;}'
```

В `diagnostics` ожидается:

```json
{
  "phase": "syntax",
  "message": "Expected expression, found SEMICOLON ';'",
  "offset": 21,
  "line": 1,
  "column": 22
}
```

Ошибочное `r=;` не попадёт в AST, а правильное `x=2;` сохранится.
Это демонстрация режима паники: парсер ищет `;`, `}`, конец файла или начало
следующей команды и продолжает разбор. При ошибке определения он ищет
следующее определение с учётом вложенности фигурных скобок.

### Другие отрицательные примеры

```bash
python3 -B parser.py --text 'f(x:int returns r:int {}'
python3 -B parser.py --text 'f() returns r:int {} ;'
python3 -B parser.py --text 'f() returns r:int {r=1+;}'
python3 -B parser.py --text ''
```

Это незакрытая скобка, лишний токен, отсутствующий операнд и пустой ввод.
В каждом случае ожидается непустой `diagnostics` с сообщением и позицией.
Команды с ошибочными входами завершаются с кодом `1` — это ожидаемо.

При лексической ошибке, например символе `@`, результат содержит `ast: null`
и диагностику с `phase: "lexical"`. После синтаксической ошибки возможно
частичное дерево. Для дальнейших этапов используйте AST только при пустом
`diagnostics`.

Коды завершения: `0` — разбор без ошибок, `1` — диагностика или ошибка чтения
файла, `2` — неправильные аргументы запуска.

Лексер использует самое длинное совпадение, при равной длине — порядок правил.
Пробелы и комментарии пропускаются с сохранением координат следующих токенов;
в конце добавляется `EOF` с позицией. Алгоритмы HW1 включены в `automata.py`,
поэтому отдельно запускать HW1 или генерировать таблицы перед запуском не нужно.

## Грамматика и принятые правила

Финальная грамматика — [grammar.ebnf](grammar.ebnf).
В ней полностью раскрыты синтаксис и лексика: идентификаторы через буквы,
цифры и `_`, целые литералы без ведущих нулей, зарезервированные слова,
пробелы, переводы строк и комментарии. Неопределённых категорий токенов нет;
конец ввода означает, что правило `module` должно разобрать весь текст.
Спецификация языка — [funny.ru.md](../../funny.ru.md): указанного в условии
пути `docs/funny.ru.md` в репозитории нет.

Для выражений устранена левая рекурсия: вместо `E → E + T | T` используется
`E → T { + T }`. Повторение реализовано циклом `chain()`. Общие префиксы
определений и присваиваний разбираются один раз, затем выбирается продолжение.
Подграмматика выражений LL(1); для полной грамматики отдельно заданы правила
для необязательных `else` и пустых контрактов, поэтому утверждение об отсутствии
LL(1)-конфликтов не относится ко всему языку.

Приоритеты от сильного к слабому:

| Операции | Ассоциативность |
| --- | --- |
| Скобки, вызовы, индексы | Первичные и постфиксные конструкции |
| Унарный `-` | Справа |
| `*`, `/` | Слева |
| `+`, бинарный `-` | Слева |
| `==`, `!=`, `<`, `<=`, `>`, `>=` | Одно сравнение; цепочки запрещены |
| `not` | Справа |
| `and` | Слева |
| `or` | Слева |
| `->` | Справа |

Особенности и согласование с материалами курса:

- Функцию можно записывать с `function` и без него. Для формулы с `=>`
  префикс `function` запрещён; завершающая `;` у формулы необязательна.
- `returns` обязателен и содержит хотя бы одно имя. Параметры и возвраты
  требуют тип `int` или `int[]`; в `uses` тип необязателен.
- `requires`, `ensures`, `invariant` могут отсутствовать или быть пустыми.
  Если следующий токен начинает выражение, он относится к контракту.
  Поэтому после пустого `ensures` или `invariant` перед присваиванием нужен блок.
  Пустой и отсутствующий контракт в AST представлены `null`.
- `else` относится к ближайшему `if`.
- Разрешены повторная индексация и индексация результата вызова.
  Допустимость типов проверяется позднее.
- Для арифметики, условий и предикатов используется общая грамматика выражений.
  Записи вроде `true+1` синтаксически принимаются; проверка типов относится к HW3.
- Алфавит — ASCII, в том числе в комментариях. Для импликации нужна `->`,
  а не Unicode-стрелка `→`. Идентификаторы допускают `_` по правилам HW1/P01.
  Числа с ведущими нулями (`00`, `01`) запрещены.
- Пустая программа, отдельная лишняя `;` и вызов как самостоятельная команда
  являются синтаксическими ошибками.

## Использование из Python

Из папки `homeworks/hw2` можно импортировать API для следующих домашних работ:

```python
from parser import parse

result = parse("f() returns r:int {r=1;}")
if result["diagnostics"]:
    print(result["diagnostics"])
else:
    tree = result["ast"]
```
